# Job Seeker

Job Seeker 是一个运行在本机的多平台求职辅助工具，目前支持 BOSS 直聘、智联招聘和前程无忧。系统通过浏览器用户脚本读取岗位信息，使用配置的模型完成岗位评分，并按照平台流程执行后续操作。

- BOSS 直聘：读取推荐岗位或关键词搜索结果，完成岗位分析、筛选和打招呼。
- 智联招聘：轮询用户配置的岗位列表，完成岗位分析、筛选和“立即投递”，并验证投递结果。
- 前程无忧：轮询用户配置的岗位搜索页，打开职位详情路由读取真实 JD 完成评分，并在列表页完成投递。
- 各平台相互隔离：一个平台因登录、验证码或页面异常暂停时，其他平台可以继续运行。
- 统一评分：复用“学历专业、技术栈、项目经验”三项评分标准、阈值和岗位历史。
- 本地优先：配置、运行记录和岗位历史保存在本机，模型可使用 Ollama 或 OpenAI 兼容接口。

> [!IMPORTANT]
> 智联招聘平台的人机检测和安全校验触发比较频繁。如果系统突然暂停，尤其是只有某一个平台通道暂停，通常可能是程序检测到了登录校验、验证码、安全验证、访问频率限制或页面异常，并不一定是程序故障。请先在浏览器中人工完成验证，确认岗位列表恢复正常后，再执行对应平台的恢复命令（例如 `resume zhaopin` 或 `resume job51`）。不要连续刷新、反复恢复或尝试绕过平台验证。

## 核心运行策略

1. 系统先读取岗位基本信息和 JD，再通过模型完成三项评分。
2. 只有达到配置阈值且模型建议继续的岗位，才会进入平台后续流程。
3. 各平台分别维护页面、心跳、列表扩展状态、成功计数和暂停原因。
4. 各平台、启动预热和配置生成共用同一个模型执行门，默认一次只运行一个模型任务，避免本地设备同时加载多个请求。
5. BOSS 在列表不足时使用自适应滚动；智联和前程无忧在详情页处理完毕后定位并点击“下一页”，通过页码、网址和岗位集合验证翻页结果。智联页面刷新后以当前真实页为准，旧翻页次数会在页码或岗位集合不一致时归零，不会自动追到刷新前的页码。
6. 岗位 URL、稳定岗位 ID 以及同平台公司名加职位名会依次参与去重；脚本启动时会加载近期处理历史，避免刷新后重新评分同一批岗位。
7. 登录失效、验证码、安全验证、访问过频、平台上限或结果无法确认时，系统采用保守暂停策略。
8. 所有页面操作都会加入随机等待；智联和前程无忧相邻两次投递点击之间默认保持 3～10 秒随机间隔。

## 快速开始

### 运行环境

- Windows 10 或 Windows 11
- Python 3.10 或更高版本
- Chrome、Edge 或其他支持 Tampermonkey 的 Chromium 浏览器
- Tampermonkey 扩展
- Ollama，或可用的 OpenAI 兼容模型接口

项目启动器会优先使用 `.venv`，首次运行时可自动创建虚拟环境并安装依赖。

### 第一次启动

1. 根据需要双击对应入口：

   - `start_all.bat`：启动全部已启用的平台。
   - `start_boss.bat`：只启动 BOSS。
   - `start_zhaopin.bat`：只启动智联。
   - `start_job51.bat`：只启动前程无忧。

   启动器只会打开已启用平台对应的页面；如果某个平台在配置中关闭，`start_all.bat` 会跳过它的页面和调度。

2. 执行 `config`，确认平台、模型、评分阈值和投递参数。
3. 执行 `resume` 导入或更新简历内容，再用 `profile` 检查识别结果。
4. 使用 BOSS 时，执行 `tags` 和 `greeting` 配置搜索标签与招呼语。
5. 执行 `script`，按照提示分别安装需要的平台用户脚本。也可以直接打开：

   ```text
   BOSS:     http://127.0.0.1:33333/userscripts/boss.user.js
   智联:     http://127.0.0.1:33333/userscripts/zhaopin.user.js
   前程无忧: http://127.0.0.1:33333/userscripts/job51.user.js
   ```

6. 在浏览器中分别登录需要启用的平台，并打开岗位列表页：

   - BOSS 直聘：<https://www.zhipin.com/web/geek/jobs>
   - 智联招聘：`zhaopin_job_urls` 中配置的岗位列表页，默认回退地址为 <https://www.zhaopin.com/recommend>；推荐直接填新版搜索页，例如 <https://sou.zhaopin.com/?kw=算法工程师>
   - 前程无忧：`job51_job_urls` 中配置的搜索页，默认为 <https://we.51job.com/pc/search?keyword=算法工程师>

7. 安装或更新用户脚本后刷新平台页面，回到控制台执行 `status`，确认对应平台已经连接。
8. 点击平台页面左下角面板的“开始”，或在控制台执行 `start`。面板还可以暂停、继续或结束当前平台，不影响其他平台。

四个启动器都只负责准备后端和打开对应平台页面。是否正式开始处理岗位，统一由网页左下角面板控制，避免误启动，也不再区分容易混淆的“手动版”和“自动版”。

## 平台流程

### BOSS 直聘

- 优先读取用户配置的推荐 Tab，再按搜索标签处理关键词岗位。
- 列表不足时自动滚动加载，达到页面末尾后进入下一来源或随机冷却。
- 岗位通过评分和历史检查后，进入打招呼流程。
- 公司联系次数、搜索频率和每日搜索次数均可通过配置限制。

### 智联招聘

- 默认使用 `https://www.zhaopin.com/recommend`，也可以配置多个岗位列表网址并依次轮询。`https://sou.zhaopin.com/` 的新版搜索页同样被接受，适合直接填关键词搜索地址。
- 配置的搜索地址通常会被智联 302 到规范化后的列表页，落地地址和配置地址对不上。脚本只在必要时做一次纠正跳转，之后就以实际落地的列表页继续工作，不会反复重载页面。
- 当前页岗位处理完毕后按这个顺序继续找岗位：**先翻页**（点击可用的“下一页”）→ **翻不动就滑动**（下滑加载懒加载出来的新卡片，最多 `search_result_scroll_rounds` 次）→ **滑动也没有新岗位才切换下一个岗位网址** → 所有网址都耗尽后**才进入冷却**。
- 新版列表页是懒加载的，没有“下一页”按钮并不代表岗位处理完了；早期版本漏了滑动这一步，会在只处理一两个岗位后就误判耗尽并冷却。状态页里会分别显示“智联翻页”和“智联滑动”的轮数与结果，方便确认卡在哪一步。
- 系统按“页面结构化数据、详情语义元素、岗位卡片”的顺序提取公司、薪资、城市和 JD，再使用与 BOSS 相同的模型提示词评分。个别字段仍缺失时不会盲目暂停，而会按批次输出数据质量汇总。
- 如果刷新后实际页码或岗位集合与保存状态不同，翻页计数会归零并从当前页继续；20 页上限只统计当前真实页面会话中已经确认成功的翻页。
- 已显示“已投递”的岗位会直接记录并跳过。
- 通过评分后，只在当前岗位详情区域操作可见且可用的“立即投递”按钮。
- 简历确认界面只有在默认简历唯一，或简历名称与 `zhaopin_resume_name` 精确匹配且没有补充问题时，才会自动确认。
- 遇到岗位问卷、附件要求、多份简历无法确认或异常提示时，仅暂停智联通道，等待人工处理。
- 投递成功后会弹出「已向对方发送简历和打招呼语」提示，按钮为“留在此页”和“继续沟通”。脚本识别为成功并点“留在此页”，不会点“继续沟通”（那会跳到聊天页而离开岗位列表），也不会把这个提示误判成需要人工处理的异常。
- 单个岗位缺少预期详情元素时会跳过当前岗位；连续 3 个岗位出现同类元素异常时才暂停智联，避免偶发失效岗位中断整轮任务。
- 点击投递后，必须观察到按钮变为“已投递”才记为成功。结果无法确认时会保留详情页、记录未知状态并暂停智联，避免重复点击。

### 前程无忧

- 轮询 `job51_job_urls` 中配置的岗位搜索页，默认为 `https://we.51job.com/pc/search?keyword=算法工程师`，可以配置多个关键词搜索页并依次使用。
- 当前页岗位处理完毕后翻到下一页；页码、岗位数量和已确认的翻页结果共同决定是否继续。
- 列表页只负责调度和投递；需要完整 JD 时会在后台标签页打开 `https://we.51job.com/pc/job/<岗位 ID>` 读取详情，再由列表页使用与 BOSS、智联相同的提示词完成三项评分。
- 详情读取失败会先重试；连续失败才降级为列表卡片信息或暂停该平台，不会中断其他平台。
- 通过评分后，只在当前可见的岗位卡片上操作投递按钮，并验证状态变为“已投递”后记为成功。
- 前程无忧每次投递成功都会弹出提示框，脚本会把它识别为成功并点掉（优先点“确定/知道了”这类按钮），不会误判成需要填问卷而暂停通道。
- 已显示“已投递”的岗位会直接记录并跳过，不会重复投递。
- 投递结果无法确认时会保留详情页、记录未知状态并暂停前程无忧，需要人工核对后再恢复。
- 遇到登录页、验证码或页面结构异常时只暂停前程无忧通道，其他平台不受影响。

## 常用配置

在控制台执行 `config` 可以查看和修改配置。下面列出日常最常用的选项。

### 平台与投递

| 配置项 | 说明 | 默认值 |
| --- | --- | --- |
| `boss_enabled` | 是否启用 BOSS 通道 | `true` |
| `zhaopin_enabled` | 是否启用智联通道 | `true` |
| `zhaopin_job_urls` | 智联岗位列表网址，可配置多个 | `https://www.zhaopin.com/recommend` |
| `zhaopin_resume_name` | 自动确认时要求精确匹配的智联简历名称；留空时仅接受唯一默认简历 | 空 |
| `zhaopin_apply_delay_min_seconds` | 智联投递最小间隔 | `3` |
| `zhaopin_apply_delay_max_seconds` | 智联投递最大间隔 | `10` |
| `zhaopin_max_applications_per_run` | 智联单次运行投递上限，`0` 表示关闭限制 | `0` |
| `zhaopin_max_applications_per_day` | 智联每日投递上限，`0` 表示关闭限制 | `0` |
| `job51_enabled` | 是否启用前程无忧通道 | `true` |
| `job51_job_urls` | 前程无忧岗位搜索页网址，可配置多个 | `https://we.51job.com/pc/search?keyword=算法工程师` |
| `job51_resume_name` | 前程无忧投递时要求使用的简历名称；留空时使用平台默认简历 | 空 |
| `job51_apply_delay_min_seconds` | 前程无忧投递最小间隔 | `3` |
| `job51_apply_delay_max_seconds` | 前程无忧投递最大间隔 | `10` |
| `job51_max_applications_per_run` | 前程无忧单次运行投递上限，`0` 表示关闭限制 | `0` |
| `job51_max_applications_per_day` | 前程无忧每日投递上限，`0` 表示关闭限制 | `0` |
| `max_contacts_per_company` | BOSS 同一公司的联系次数上限 | `1` |

建议首次使用智联或前程无忧时设置较小的单次和每日投递上限，确认页面行为稳定后再逐步调整。

### 模型与评分

| 配置项 | 说明 | 默认值 |
| --- | --- | --- |
| `model_provider` | 模型来源，例如 Ollama 或 OpenAI 兼容接口 | `ollama` |
| `ollama_host` | Ollama 服务地址 | `http://127.0.0.1:11434` |
| `openai_api_base` | OpenAI 兼容接口地址 | `https://api.openai.com/v1` |
| `think_model` | 岗位评分使用的模型 | `qwen3:1.7b` |
| `score_threshold` | 进入后续流程的最低总分 | `70` |
| `disable_model_thinking` | 是否请求关闭模型思考模式 | `true` |
| `model_max_concurrency` | 模型最大并发数 | `1` |
| `show_model_reasoning` | 是否在控制台显示模型评分说明 | `false` |

使用需要密钥的兼容接口时，可以在启动前设置环境变量：

```powershell
$env:OPENAI_API_KEY="你的密钥"
```

默认并发数为 1。需要提高到 2 时，请先执行 `doctor concurrency`；该命令会使用当前模型配置发起两次轻量真实请求，通过后再由用户确认是否启用并发。

启动时的模型预热也会经过同一个执行门，不会再与各平台的岗位评分同时抢占模型。若 Ollama 拒绝连接，系统会立即暂停全局任务，避免多个平台继续消耗岗位并重复失败。

### 列表扩展与频率

| 配置项 | 说明 | 默认值 |
| --- | --- | --- |
| `search_result_scroll_rounds` | 单个岗位来源最多扩展轮次；BOSS 表示滚动次数，智联和前程无忧表示翻页次数 | `20` |
| `preferred_feed_mode` | BOSS 推荐来源模式 | `all_custom_tabs` |
| `preferred_feed_max_jobs_per_tab` | 每个推荐 Tab 的岗位上限，`0` 表示不限 | `0` |
| `search_round_cooldown_min_minutes` | 搜索来源耗尽后的最小冷却时间 | `1` |
| `search_round_cooldown_minutes` | 搜索来源耗尽后的最大冷却时间 | `5` |
| `tag_search_delay_seconds` | BOSS 标签切换最小等待 | `20` |
| `tag_search_delay_max_seconds` | BOSS 标签切换最大等待 | `45` |
| `max_search_submissions_per_hour` | BOSS 每小时搜索提交上限 | `6` |
| `max_search_submissions_per_day` | BOSS 每日搜索提交上限 | `30` |

降低频率、增加随机等待通常能减少平台安全校验。不要将间隔设置得过短。

## 暂停与恢复

| 情况 | 系统行为 | 建议处理 |
| --- | --- | --- |
| 某平台登录失效、验证码、安全验证或访问过频 | 只暂停对应平台 | 人工处理页面后点击该平台面板的“继续”，或执行对应恢复命令 |
| 智联或前程无忧点击后无法确认是否已投递 | 暂停对应平台并保留详情页 | 人工核对投递记录，不要再次点击；确认后再恢复该平台 |
| 岗位问卷、附件要求或简历无法唯一确认 | 暂停智联 | 人工完成或跳过当前岗位，再恢复智联 |
| 一个岗位列表确认耗尽 | 切换下一个来源；全部耗尽时进入冷却 | 等待冷却结束即可 |
| 模型连续失败、后端中断或执行全局暂停 | 所有平台同时停止继续操作 | 先运行 `doctor` 排查，再恢复全局任务 |

页面面板的“结束”只停止当前平台；“开始”会检查模型和必要配置后创建新运行。全局模型故障仍会同时暂停所有平台，模型恢复后可以从任一平台面板重新开始。

`status` 中每个平台的主状态固定表示岗位调度页。临时详情页或聊天页显示在 `recent_activity`，不会再覆盖列表页的滚动、翻页和当前调度动作；本轮成功数以已经确认的打招呼或投递事务为准。

## 使用建议

- 第一次运行智联或前程无忧投递时，请在浏览器旁观察至少一次完整流程，确认岗位详情、简历选择和“已投递”状态符合预期。
- 智联人机检测较频繁，出现暂停时先检查浏览器页面，不要立即连续执行恢复命令。
- 投递结果未知时，先到对应平台的投递记录中人工核对，避免重复投递。
- 初次使用建议设置保守的投递上限和更长的随机间隔。
- 保持需要启用的平台列表页已登录；不要同时手动打开大量相同平台的调度页面。
- 项目更新后，执行 `script` 检查用户脚本版本，并在 Tampermonkey 中更新后刷新平台页面。
- BOSS 与智联、前程无忧现在是三个独立用户脚本；如果浏览器中仍有旧版同时匹配两个网站的 `Job Seeker`，请更新旧脚本并分别安装三个新入口，避免重复运行。
- 修改模型来源、地址或模型名称后，模型并发会回到 1；需要并发时重新执行 `doctor concurrency`。
- 大幅调整配置或升级前执行 `backup`，保留数据库备份。
- 诊断报告可能包含岗位、公司和本地配置摘要，对外发送前请先检查内容。

## 常见情况

### 智联通道经常暂停

这是最常见的情况。先查看智联页面是否出现登录页、滑块、短信验证、安全提示、访问频率提示或异常弹窗。完成人工验证后返回配置的岗位列表页并刷新，再执行：

```text
status
resume zhaopin
```

也可以在人工验证完成后点击智联页面左下角的“继续”。如果投递结果显示为未知，必须先人工核对，不能直接重复投递。

### 智联页面一直闪烁（反复重载）

表现为智联标签页每隔几秒自己刷新一次，`status` 里能看到大量“切换智联岗位页”，但一个岗位都没处理。原因是配置的搜索地址会被智联 302 到规范化后的列表页（例如 `sou.zhaopin.com` → `www.zhaopin.com/jobs`），落地地址和配置地址永远对不上，早期逻辑就会一直“跳回配置页”。

现在脚本只在必要时纠正跳转一次，之后直接使用实际落地的列表页继续工作。如果升级后仍然闪烁，按下面顺序检查：

1. 确认 `data/config.json` 里的 `zhaopin_job_urls` 是 `https://` 开头的智联地址；启动时控制台会把无法识别的地址打印成 `[警告] 智联岗位列表网址已忽略 ...`。
2. 用浏览器直接打开该地址，确认没有跳登录页。跳到登录页说明未登录，先完成登录再刷新。
3. 执行 `script` 确认智联脚本版本已经是最新，必要时在油猴里手动更新脚本并刷新页面。

### 前程无忧通道经常暂停

前程无忧的搜索页、详情页和投递流程都可能触发暂停：登录失效、验证码、页面结构变化、无法打开详情页或投递结果无法确认时，只会暂停前程无忧通道。处理方式与智联相同，先人工确认页面恢复正常，再执行：

```text
status
resume job51
```

前程无忧的岗位详情会在后台标签页打开。如果浏览器拦截了新标签页或弹窗，脚本读不到 JD 就会持续失败，请允许 `we.51job.com` 打开新标签页后重试。投递结果未知时同样必须先人工核对，再恢复通道。

详情页是前端渲染的，后台标签页首帧可能很慢，看起来就是“打开了白屏、没有界面”。脚本会先等职位名称元素出现再读取，读完后无论成功失败都会回收该标签页；如果始终读不到，就退回用列表卡片信息评分，不会留下空白标签页。控制台里出现“前程无忧详情页未找到职位名称”时，说明该次详情读取超时，通常是被登录页或拦截页替换了。

### 脚本版本没更新会一直报旧问题

后端按 `@version` 判断是否需要更新油猴脚本，更新脚本后**必须刷新平台页面**，正在运行的旧页面仍会执行旧代码。启动时如果控制台提示 `已打开 xxx 脚本安装/更新页`，请到该页面确认安装，再逐个刷新平台页；也可以执行 `script` 查看各平台当前上报的版本是否与 expected 一致。

**注意**：2026.07.27.1 这个版本号曾经在多个提交里没有跟着代码变更提升，油猴因此一直认为脚本是最新的，浏览器里跑的很可能是几个月前的旧代码。现在版本号已经提升到 2026.09.17.6，三个平台分别使用独立的油猴脚本，需要**各自更新一次并刷新页面**。判断方法：执行 `status`，看各平台上报的 version 是否等于 `2026.09.17.6`；显示 `2026.07.27.1` 的就是还没更新。

### 投递弹窗被误判（已修复）

2026.09.17.6 之前，投递成功后的提示弹窗会被误判：智联报“智联投递弹窗无法安全确认”、前程无忧报“前程无忧投递需要填写问卷、附件或补充信息”，然后暂停整个通道——但那次投递其实已经成功了。现在这两种提示都会被识别为投递成功并自动关掉。

同一版本还修掉了前程无忧“投递结果无法确认 / 按钮未变为已投递”：投递后列表会重渲染，原来复用点击前的卡片节点已经脱离文档，读不到按钮状态；现在每轮都按职位重新定位卡片（先用职位名，再用岗位 ID 的详情链接反查）。

还有两个更隐蔽的问题也一并修了：

- `simpleDialogs()` 的 `[class*="dialog"]` 会命中**覆盖整页的 wrapper**。这种容器的文字包含整个页面（站点导航、用户名、搜索筛选项都在里面），于是搜索框被当成“问卷输入项”误报需要人工处理，成功提示的签名也变成了整页文本。现在按文字长度只取最内层的真弹窗（`compactDialogs`，上限 600 字），成功提示也不限于 `role=dialog`，toast/message 节点同样能识别。
- 确认弹窗阶段的返回值原本被调用方丢弃。弹窗阶段已经识别出成功提示后，代码还会继续等按钮变成“已投递”，等不到就记成“结果无法确认”并暂停。现在弹窗阶段一旦确认成功就直接记为已确认。

如果升级后仍然出现投递相关报错，报错信息末尾会附带弹窗的真实内容（`文字=... | 按钮=... | 输入项=...`），无法确认时还会带上卡片上的按钮文字，把这些发出来即可定位。


### 平台显示未连接或脚本离线

1. 确认后端控制台仍在运行。
2. 执行 `script` 检查安装地址和版本。
3. 确认 Tampermonkey 已启用该脚本。
4. 刷新对应平台页面，等待几秒后再次执行 `status`。

### 浏览器需要打开开发者模式脚本才能正常注入

Chrome 和 Edge 出于安全策略，有时会拦截未开启“开发者模式”时注入的扩展用户脚本，表现为：脚本已安装但平台页面左下角面板不出现，`status` 一直显示“未连接”或脚本离线。

打开方式（以 Chrome 为例，Edge 相同）：

1. 在地址栏进入扩展管理页：`chrome://extensions`（Edge 为 `edge://extensions`）。
2. 找到 **Tampermonkey** 扩展。
3. 打开卡片右上角的**“开发者模式”**开关（Developer mode）。

开启后会提示重启浏览器或重新加载扩展，按提示完成后刷新对应平台页面，再执行 `status` 确认已连接。若面板仍未出现，回到 Tampermonkey 管理页确认脚本已启用，并按需更新脚本后再次刷新页面。

### 模型评分为 0 或持续失败

执行 `doctor` 检查模型服务地址、模型名称和密钥。使用 Ollama 时，确认 Ollama 已启动且配置的模型已经下载；使用兼容接口时，确认接口地址和 `OPENAI_API_KEY` 有效。

### 模型评分提示“模型没有返回内容”或连续失败后暂停

如果日志显示类似“模型没有返回内容（已重试3次）”，且所有岗位评分都变成 0 分、最终自动化被暂停，很可能是**评分令牌上限被设置得太小**。推理模型即使关闭了思考模式，也会先输出较长的推理过程，如果令牌预算被推理耗尽，就没有剩余空间再生成最终的 JSON 评分，导致模型“没有返回内容”。

排查方式：打开 `data/config.json`，检查 `job_score_num_predict_think_off` 和 `job_score_num_predict_think_on`。默认值为 `-1`（不限制令牌，由系统在检测到完整评分后主动截断）；如果被设成了类似 `200` 的较小数值，请改回 `-1`，保存后重新启动后端。同样位置也可以通过控制台的 `config` 命令调整。

> 小贴士：长职位描述会放大该问题。改为不限制令牌后，即使 JD 较长模型通常也能正常输出评分。

### 岗位列表没有继续加载或翻页

先执行 `status`。BOSS 重点查看滚动模式、目标、轮次和岗位数量变化；智联和前程无忧重点查看当前真实页码、成功翻页次数、下一页结果和翻页前后的岗位数量。刷新智联页面后看到翻页次数归零属于保守恢复，不是丢失进度；近期岗位历史会阻止同一批岗位被重复评分。如果智联或前程无忧页面能够人工点击下一页但系统没有翻页，优先更新用户脚本并刷新页面；如果已经显示下一页禁用、列表耗尽或进入冷却，则属于正常状态。

### 详情页没有打开

检查浏览器是否拦截了新标签页或弹窗，并允许 BOSS、智联、前程无忧页面打开岗位详情。智联和前程无忧结果未知时，系统会有意保留详情页供人工核对。

### 端口 `33333` 被占用

关闭重复启动的 Job Seeker 控制台后重新运行启动器。如果端口仍被占用，使用 `doctor` 查看占用提示，再关闭对应的旧进程。

## 状态、日志与备份

控制台运行后可以在本机查看：

- 状态：<http://127.0.0.1:33333/status>
- 日志：<http://127.0.0.1:33333/logs>
- 岗位历史：<http://127.0.0.1:33333/history>

日常排查优先使用 `status`、`logs` 和 `doctor`。需要向开发者反馈问题时，可以使用 `report` 导出诊断信息；升级或大幅修改配置前使用 `backup` 保存本地数据。
